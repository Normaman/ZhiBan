# 账号、店铺隔离与草稿重试

## 已实现的归属模型

账号通过 `workspace_memberships` 加入工作空间；工作空间拥有多家店铺。所有者和管理员可以管理本空间的店铺、邀请客服及配置模型，客服可以处理本空间内的店铺咨询。当前按空间授权全部店铺，尚无逐店铺分配客服权限的界面。

`REGISTRATION_INVITE` 现在是部署者控制的商家开通码：注册会创建新的空间、所有者账号及一家空店铺，不加入已有商家。管理员在「店铺与成员」生成的 `team_` 邀请码用于注册客服，绑定当前空间、48 小时有效、仅能使用一次、支持撤销；数据库只保存其 SHA-256 摘要。已经存在的账号暂不支持用邀请码加入另一个团队。

V9 将原有店铺及其全部账号迁到同一个空间，保留原消息、草稿、审批、知识版本及模型配置。`app_users.shop_id` 只作为登录默认店铺，`app_users.role` 只保留账号兼容字段；实际业务权限以当前空间成员关系为准。成员关系和账号停用状态在每次业务请求时重新读取，不依赖登录时缓存的角色。

## 店铺切换与请求权限

顶栏可以选择有权限的店铺。前端仅保存所选店铺 ID，刷新后恢复；不保存账号密码、API Key 或登录态到浏览器存储。退出和重新登录会清除该选择。

顶栏「管理店铺」可以直接进入管理页。新店铺入口只创建真实拼多多店铺，创建后进入授权流程。切换时保留顶栏并暂时隐藏旧店铺业务内容。列表可移除非当前店铺；移除会永久清除该店铺的业务数据和登录资料，最后一家店铺、部署默认店铺、有未完成任务或发送结果待核实的店铺不能移除。店铺名称、头像和主营类目通过已核对身份的平台资料同步；手工显示名称不改动拼多多原店名，头像失败时使用固定尺寸的店铺图标。

`X-Shop-Id` 只选择数据范围，不能授予权限。`ShopAuthorizationFilter` 核对当前账号的成员关系，再建立只在请求线程内有效的 `ShopScope`；后台任务显式打开所属店铺范围，并在结束时清理。缺省选择账号默认店铺；默认店铺权限已撤销时，选择仍有权限的首家店铺。显式请求无权限店铺返回 403，不静默跳到其他店铺。

会话、商品快照、知识版本、模型配置、阅读记录和审计均按店铺查询。旧消息、草稿、生成任务或发送命令 ID 不能绕过店铺校验。知识版本增加店铺内的 `version_label`，内部 ID 独立生成，不同店铺可使用相同版本名称。

切换时前端清空旧会话和未提交页面状态、卸载旧页面，并使迟到请求失效。正在进行审批等写操作时禁止切换；后台生成任务不随页面切换改变归属。`jobs.shop_id` 在任务创建事务中保存，执行器始终使用任务中的店铺。

模型配置和密钥按店铺隔离，新店铺不会继承其他店铺的配置。环境变量模型配置仅对原默认店铺生效。远程模型服务默认只允许 `api.deepseek.com`、`api.openai.com` 的 HTTPS 默认端口；部署者可通过 `MODEL_ALLOWED_HOSTS` 配置其他确切域名。开发用回环模型地址仅对默认店铺生效，且须显式打开 `ALLOW_LOCAL_MODEL_ENDPOINTS`。浏览器不能通过自定义域名让服务器连接任意内网地址。

这属于应用层授权隔离，没有启用 PostgreSQL RLS；内部服务共享令牌仍是部署级信任边界，不能公开给普通商家。

## 使用与接入第二家店铺

1. 原管理员登录后，在「店铺与成员」添加真实拼多多店铺，完成商家网页登录和身份确认后从顶栏切换。
2. 新商家使用部署者提供的商家开通码注册，进入自己的空空间。新店铺的知识库和模型需要自行配置。
3. 邀请客服时，从该空间的管理页生成客服邀请码，客服在注册页使用；不要向客服提供商家开通码或整份环境文件。

每家新店铺使用独立的登录资料和连接状态。添加店铺后打开授权页登录并核对平台身份。确认后，后端验证 WebSocket 身份、加密保存凭据、绑定店铺，并将连接器登记到共享持久卷中的注册表。Agent 最多约 5 秒发现连接并建立独立 Runtime、WebSocket 和执行日志。新店铺不会自动获得其他店铺的政策、商品资料或模型配置。

首次授权会生成独立的 `/data/shops/{shop_id}` 凭据目录；Docker Compose 中 Core 与 Agent 共享 `/data/connectors.json` 注册表及 `agent-data` 持久卷。旧版本中的演示店铺会迁移为未授权店铺，历史会话不会自动删除。登录资料不会传回浏览器，也不会覆盖其他店铺的凭据。拼多多身份已被其他业务店铺绑定时，系统拒绝重复登记。真实发送保持关闭。

每个店铺从工作台授权页连接拼多多。Spring Boot 在部署主机内创建登录浏览器、核验身份并保存加密凭据；Python Agent 不接收 Cookie 或密钥。不要把账号密码或部署密钥写入命令行、日志或仓库。

新增连接器强制保持真实发送关闭；默认真实连接器默认也关闭，仅支持部署端明确指定一家店铺内的一个测试会话限时开放，两个服务校验相同会话与有效期。没有使用第二家真实店铺完成端到端验收：当前多店铺功能通过隔离数据库、身份错误与凭据拒绝测试验证，不能替代平台实测。

## 草稿重试

未审批的最新咨询可以点击「重新生成草稿」，包括资料不足、生成失败和人工拒绝后的场景。补充知识后重新生成会固定新的知识版本，保留原消息与会话，更新同一草稿的版本。生成中不能重复启动；审批、发送中、已发送或待核实的内容不能被覆盖。退款等风险检查仍然生效，重试不能绕过转人工规则。

「重试发送」沿用原审批内容，只允许明确失败、会话版本仍匹配的命令；`send_unknown` 禁止重复发送。人工接管后可在独立输入框回复，人工记录与 AI 草稿分开保存，共用发送执行机制；恢复 Agent 不重发旧回复。真实发送默认关闭，指定测试会话的限时授权见 [运行手册](copilot-runbook.md)。

## 性能与并发边界

商品详情由 PostgreSQL 持久任务逐件同步，进程中断可继续领取，重复启动返回现有运行任务。一个店铺的商品详情串行同步，连接器在每次详情请求后留出间隔；发送、回复生成优先于商品补齐任务。基础同步成功后会自动开始详情同步。界面显示总数、已完成数和失败数，失败任务有有限重试，全部结束后可以再次同步。

已核对商品详情接口 `/glide/v2/mms/query/commit/on_shop/detail` 的 `goods_id`、`mall_id`、`cats`、`skus[].spec`、图片和说明；商品参数接口 `/latitude/goods/goodsProperties` 的 `properties` 与官方页面使用的 `name/values` 结构对应。只提取明确的商品字段，不保留整份商家资料或详情返回。店铺主营类目与商品分类分别保存，缺失参数不根据标题猜填。商品详情仅允许读取当前店铺最近一次商品列表中的商品，平台返回的店铺与商品身份必须匹配。

详情页显示带同步时间的规格库存快照；Agent 上下文只接入已同步的分类、参数和规格名称，排除缓存库存、价格、图片及商品自由文本说明。价格库存仍通过实时只读工具获取，不能把 SKU 快照或商品级数量冒充当前规格库存。

知识库、操作记录、模型配置和店铺管理页面按需加载。隐藏标签页暂停会话和操作记录轮询，回到前台立即刷新；会话轮询不会堆叠尚未完成的请求。尚未实现 SSE、长会话增量分页或商品查询缓存。

Redis 继续负责注册限流，PostgreSQL 负责持久任务、事务与幂等。Java 默认 4 个任务线程，所有店铺的 Python Runtime 共用 4 个生成名额；工具每任务最多并行 3 个，发送每店铺串行。尚未实现店铺公平调度、额度管理或分布式连接器选主，浏览器会话也还没有共享到 Redis。

## 验证与后续边界

本地验证使用 Agent 隔离测试和 Spring Boot 集成测试：

```sh
conda activate dl
python -m pytest -q services/agent-service/tests
mvn -f services/core-service/pom.xml test
```

合成数据只在测试进程中创建，不注册产品 API，也不连接拼多多或发送消息。部署浏览器检查需显式设置 `RUN_LIVE_READONLY=1` 或 `RUN_DEPLOYMENT_CSP_CHECKS=1`。

后续仍需完成：检索质量与向量/混合检索、会话摘要及受控长期记忆、模型调用前脱敏、留存和删除流程、成员生命周期管理、负载测试及第二家真实店铺接入验收。MCP 和商品发布助手仍未实现，客户聊天不会自动进入测试集或训练集。

## 成员停用与移除

管理员在「店铺与成员 → 团队成员」停用、启用或移除当前工作空间的客服成员。不能操作自己、所有者或管理员。操作需要最近五分钟内完成密码验证，并携带成员修订号，旧列表发起的冲突请求返回 409。

停用和移除仅改变当前工作空间的成员关系，不删除账户、已发送消息或历史审批。店铺权限在每次业务请求时读取数据库，已有登录会话也不能继续访问被停用或移除的空间；同一账户在其他空间的权限不受影响。启用用于恢复停用的成员，移除操作不提供恢复入口。

店铺移除先检查当前空间归属、默认/当前店铺及进行中的任务，停止店铺连接后在事务内再次校验，并清理事件暂存、分段发送日志、任务 Outbox、知识变更及其修订历史，再删除父记录。数据库删除失败时恢复连接登记。此功能不用于单独清除历史消息或审计记录。
