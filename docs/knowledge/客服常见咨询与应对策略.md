# 客服常见咨询与应对策略

本文用于梳理客服助手应如何理解、查证和组织常见电商回复。它是产品与 Agent 设计说明，不是某家店铺的业务规则，也不会自动成为运行时知识；店铺事实必须由商品数据、平台接口或已审核发布的知识库提供。

## 一、统一处理方法

每条买家消息按同一条主线处理，不为每种说法单独增加一条提示词规则：

1. **理解要解决的事**：识别买家是在问商品、订单、政策，还是提出实际操作；结合上下文解析“这个”“刚才那款”等指代。
2. **确定对象和范围**：锁定商品、规格、订单或地区。只有对象不明确且会改变答案时才追问。
3. **找对应的可信来源**：实时事实查平台数据，店铺承诺查已发布规则，商品说明查商品资料。来源缺失时不能用常识补齐。
4. **逐项回答**：一条消息有多个问题时分别处理；已能确认的部分先回答，只对缺失部分说明限制或转人工。
5. **简短表达并收住**：先给结论，再给必要条件。通常一到三句，不重复问题、不附加未经请求的推荐，也不承诺系统没有执行的操作。

信息来源优先级：当前平台实时数据 → 当前商品资料或订单事实 → 店铺审核发布的规则/FAQ → 澄清问题或人工核实。回答规范只决定表达方式，不是业务事实来源。

## 二、常见咨询场景

| 场景 | 买家常见问法 | 应查来源与处理方式 | 何时澄清或转人工 |
| --- | --- | --- | --- |
| 商品搜索与在售情况 | “有德国马克吗？”“还有蓝色的吗？”“有没有类似款？” | 按名称、品类、品牌或属性搜索当前店铺商品；有多项结果时简洁列出可区分的信息，不将搜索未命中说成平台绝对没有。 | 搜索词过于宽泛且结果太多时问一个关键偏好；平台检索失败时说明暂不能确认。 |
| 规格、属性与使用 | “多大尺寸？”“什么材质？”“适配这个型号吗？”“一份有几件？” | 查商品标题、属性、描述、SKU 和已发布商品知识；区分规格值、销售单位数量、用途/兼容性。 | 兼容性没有明确资料时不要根据外观或常识判断；必要时询问设备型号或转人工。 |
| 价格、比价与优惠 | “多少钱？”“哪个规格便宜？”“这几款哪款最低？”“能优惠吗？” | 查当前商品或匹配商品的实时 SKU 价格；明确比较范围和价格口径。优惠券、活动、运费及最终到手价仅在来源明确时说明。 | 商品或规格不明确且影响价格时追问；没有议价/改价能力时说明以页面展示和平台优惠为准，不声称已改价。 |
| 库存、缺货与补货 | “还有几件？”“红色有货吗？”“什么时候补货？” | 查当前商品对应 SKU 的实时库存；明确数量是可售库存还是每份包含数量。补货时间只查已确认资料。 | 库存接口失败或未返回时说暂无法确认；没有补货安排时不猜日期。 |
| 发货与预售 | “什么时候发？”“预售多久发？”“周末发货吗？” | 区分店铺通用规则与当前商品设置；订单已经形成时再判断是不是在问这笔订单的进度。 | 缺少适用商品/预售批次规则时补问或转人工；不说“已催单”“马上发”等未经执行的承诺。 |
| 运费与配送 | “寄到甘肃多少钱？”“包邮吗？”“偏远地区能发吗？” | 查商品运费模板、配送范围和店铺规则；涉及地区时只收集判断所需的省/地区，不要求公开完整地址。 | 运费接口没有覆盖目标地区或规则有例外时转人工；不把店铺其他商品的包邮条件套用过来。 |
| 订单、付款与取消 | “拍了吗？”“付过款了吗？”“怎么还没发？”“能取消吗？” | 先核验当前买家名下对应订单，再依据平台返回状态回答。待付款、待成团、待发货、已发货、已取消等状态不可互相推断。 | 有多个订单时请买家指出订单；订单归属或状态未核实就不下结论。取消等实际操作没有授权工具时说明入口或转人工。 |
| 物流与签收 | “到哪了？”“物流怎么不动？”“显示签收但没收到” | 只使用该订单的真实物流轨迹、节点时间和平台状态；将“平台未返回轨迹”与“物流停滞”区分开。 | 当前接口没有物流字段、轨迹异常或签收争议时转人工，不根据发货状态编造物流节点。 |
| 退换、退款与售后规则 | “七天无理由吗？”“退货运费谁出？”“退款几天到账？”“怎么申请售后？” | 查已发布、适用于该商品/订单的售后规则，简洁说明条件、入口和必要步骤。普通规则咨询可以由助手回答。 | 规则缺失、适用条件不清时转人工；实际退款、赔偿、改地址等操作须有明确授权和对应工具，否则不声称已处理。 |
| 质量问题、少发错发与投诉 | “收到破损了”“少了一件”“这是假货”“我要投诉” | 表示已理解问题，避免争辩；按店铺已发布流程提示保留必要凭证并进入人工处理。 | 争议、退款/赔偿要求、投诉升级、质量责任判断均交人工；不预先承认责任或承诺赔付。 |
| 真伪、授权与保修 | “保真吗？”“有授权吗？”“质保多久？” | 仅引用商家已审核发布且范围匹配的声明、证明或保修条件；区分商家承诺与平台认证。 | 没有可引用材料时明确需要核实，不用“绝对正品”等模型常识作保证。 |
| 发票、包装、定制与其他店铺服务 | “能开发票吗？”“可以礼盒包装吗？”“能刻字吗？” | 查店铺 FAQ、商品资料或实际可用的平台能力。 | 没有资料或办理能力就转人工/建议咨询店铺，不自行创造服务政策。 |
| 问候、感谢、考虑与结束 | “你好”“谢谢”“我再看看”“好的” | 结合上下文自然简短回应；买家同时问业务问题时仍回答业务问题。买家表示考虑时给空间，不追问、不继续推销。 | 无需为了礼貌交流要求补充商品信息；不得声称已关闭会话、留货或锁库存。 |

## 三、混合问题、连续提问和上下文

- 同一条消息包含“价格、库存、发货”时，先拆成独立问题，分别选来源；其中一项查不到，不应抹掉其他已确认答案。
- 买家连续发送多个问题时，每条问题都要保留处理状态。一次草稿可以合并展示，但必须逐条覆盖；没有回答的条目继续待处理。
- “这个、刚才那款、红色的”只从同一会话中可确认的商品卡片、订单关联和最近有效上下文解析。多个候选都合理时，问买家选哪一个。
- 人工回复可以作为理解上下文的线索，但不能自动当作已核实的平台事实或店铺政策；关键事实仍需重新查证。
- 回答已有证据的部分时，清楚标出尚未核实的部分，不把“接口没返回”“知识库没找到”和“商品不存在”混为一谈。

## 四、回答模板的结构

模板用于保持清楚，不要求模型逐字套用：

- **已核实事实**：`这款目前有货，页面显示库存为 X。`
- **带条件的规则**：`现货商品付款后按店铺规则在 X 内发出；预售商品以页面标注时间为准。`
- **对象不明确**：`您问的是哪一款？发商品链接或名称我帮您查。`
- **缺少依据**：`我暂时查不到这项信息，需要店铺核实后再答复您。`
- **需要人工处理**：`我先为您转人工核实这笔订单的情况。`

模板中的 X 必须由实际来源填充。没有真实转人工动作时，不说“已转”；没有真实查询结果时，不用“页面显示”等措辞。

## 五、人工处理边界

以下情况应停止自动给出确定结论：

- 涉及实际退款、赔偿、修改订单/地址、取消、催发货等操作，但系统没有对应授权工具或操作回执；
- 商品质量、真假责任、少发错发、签收争议或投诉升级；
- 订单归属、订单状态、物流节点或关键商品数据无法核实；
- 店铺规则互相矛盾、适用范围不明，或商家资料明确标记待确认；
- 买家提供的信息不足以区分多个商品、规格、订单或地区，且猜测会造成实际影响。

仅提到“退款”不自动等于必须转人工：解释退款入口、到账时间和退货条件属于规则咨询；要求执行退款或争议处理才进入操作/风险边界。

## 六、知识库与平台数据如何分工

| 信息 | 应维护的位置 | 例子 |
| --- | --- | --- |
| 会变化的商品价格、SKU 库存、上架状态 | 拼多多实时商品接口 | 某规格当前价格和可售数量 |
| 商品参数、用途、适配说明、包装内容 | 商品资料或绑定商品的知识条目 | 尺寸、材质、兼容型号、每份数量 |
| 店铺统一承诺和办理流程 | 店铺知识库，审核后发布 | 现货发货时限、售后入口、发票规则 |
| 商品/地区差异化设置 | 平台商品配送配置或明确绑定的规则 | 预售日期、运费模板、不可配送地区 |
| 某位买家的付款、订单、物流状态 | 当前买家对应的平台订单接口 | 已付款、待发货、物流轨迹 |
| 语气、长度、称呼和沟通禁忌 | 客服回答规范 | 简洁、不催促、不擅自承诺 |

把混杂文件导入知识库时，应先按可独立核验的事实拆条，再分类、保留来源和适用范围，供商家预览修正后发布。分类模型只能给建议，不能自动把推测变成店铺承诺。

## 七、覆盖评测应检查什么

当前 `evals/agent_cases.jsonl` 有 37 个场景、296 条样例，已覆盖部分库存、订单、售后、发货、社交交流、提示注入、近邻商品检索、长历史和记忆处理。条数多不等于覆盖充分：目前的场景更偏既有工具边界；下列场景建议纳入后续人工评审的覆盖清单，当前不代表这些能力都已接入：

- **商品类**：名称/品类搜索、同名商品、多规格价格、跨商品比价、优惠与价格口径、兼容性、尺寸/材质、使用方法、图片/商品卡片关联。
- **库存类**：SKU 有货/无货/未知、总库存与单份数量区别、查询失败、连续多个商品问题、补货时间缺失。
- **配送类**：现货/预售、节假日规则、不同地区运费、包邮门槛、配送限制、订单已发货但未揽收。
- **订单与物流类**：未付款/已付款/待发货/已发货/取消等状态、多个订单歧义、归属不匹配、轨迹停滞、已签收未收到、平台缺字段。
- **售后类**：规则咨询与执行请求区分、七天无理由条件、退货运费、退款进度、破损/少件/错件、质量争议、赔偿和投诉升级。
- **店铺服务类**：发票、包装、定制、保修、真伪/授权、优惠活动；分别覆盖“有已发布资料”和“资料缺失/冲突”。
- **对话行为类**：省略指代、多轮修正、人工与 Agent 交接、买家一次问多件事、礼貌语混合业务问题、买家表示考虑后停止推销。
- **可靠性类**：重复消息、乱序商品卡片、工具超时/空结果/部分结果、重复调用、注入指令、无权限操作、数据隐私要求。

每个覆盖点至少检查三件事：是否选对对象和来源、是否回答了全部可回答问题、缺失或高风险时是否给出正确下一步。还要包含口语、错别字、简称和上下文指代的不同表达；不能只把同一句话改几个同义词当成覆盖。

## 八、当前实现边界

当前 Agent 已有商品搜索与 SKU 查询、部分商品配送配置、订单只读查询、知识检索、逐问题处理和人工审批等能力；实际可用范围仍取决于平台接口返回字段、当前店铺数据和已发布知识。物流轨迹、发票/定制等问题不能仅凭本文视为已经接通。工具失败、字段缺失或知识无匹配时，应显示具体缺失原因并转人工/补资料，不生成看似确定的答案。
