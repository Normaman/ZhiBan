# 账号登录与会话安全

工作台使用 Spring Security 密码验证和 Cookie 会话；HTTP Basic 已关闭。脚本通过与网页相同的登录及 CSRF 流程访问业务接口，内部服务仍使用独立令牌。

## 使用

点击左侧栏底部的账号头像，打开「账号安全」：

- 查看自己的已登录设备，注销其他会话或全部会话。
- 修改密码；修改后所有设备需要重新登录。
- 查看自己的最近登录、失败尝试、密码复核和会话注销记录。

修改模型配置、删除店铺、创建成员邀请码、保存平台绑定以及注销会话等敏感操作，要求最近五分钟内验证过密码。新登录视为已完成验证，超过时间后弹出密码复核框；取消即停止原操作。密码复核不等于独立第二因素认证，当前尚未提供 TOTP、Passkey 或企业 SSO。

## 登录保护

登录、密码复核和改密校验共用三层尝试窗口，成功尝试也计数：

| 范围 | 限制 |
| --- | --- |
| 同一来源 | 五分钟 60 次 |
| 同一账号 | 十五分钟 20 次 |
| 同一账号与来源组合 | 每分钟 5 次 |

窗口达到限制返回 `429 LOGIN_RATE_LIMITED`，窗口到期后自动恢复。Redis 不可用时拒绝继续验证，不切换成无限制模式。未知账号和错误密码使用相同认证失败响应；日志不记录密码、原始 Cookie 或会话令牌。

注册仍使用独立的邀请码和注册限流机制。

## 会话

Compose 固定启用 Redis 会话存储；账号禁用状态、不可变用户 ID 和会话撤销版本在请求中重新核对。会话默认闲置 30 分钟失效，最长有效期 12 小时；后台轮询算有效访问，但不能延长最长有效期。登录更换 Session ID 并更新 CSRF Token。

Spring Session Redis 保存共享会话及账号索引，Core 重启后可恢复兼容的会话；服务端版本变更导致序列化不兼容时仍可能要求重新登录。修改密码和注销全部会话同时递增数据库撤销版本，避免并发请求保存旧会话后重新生效。删除后重建同名账号不能继承旧账号会话。会话列表返回派生引用，不暴露可用于认证的原始 Session ID。

所有浏览器写操作均要求 CSRF Token；仅内部令牌接口豁免。`AUTH_SESSION_STORE=memory` 是测试或显式本地开发选项，不支持跨实例和重启保留，不能作为 Redis 故障回退。

## 反向代理与公网部署

默认不信任 `X-Forwarded-For`，按直连来源进行保守限流。反向代理后如果需要按实际客户端地址计数，在 `infra/.env` 设置 `AUTH_TRUSTED_PROXY_CIDRS`，仅列出确实受部署者控制的代理地址或专用子网，以逗号分隔。解析从右向左逐跳验证代理，遇到第一个非可信来源停止；不接受主机名。

不要填写全网通配范围。Core 不应直接发布到公网；部署时需结合实际网络拓扑收紧代理网段。未配置时，共用代理的用户会共用来源限额，账号维度的限制仍分别生效。

公网部署按 [部署与维护](deployment.md#公网-https-部署) 启用 HTTPS 和 `SESSION_COOKIE_SECURE=true`。配置公网 `DOMAIN` 却未启用 Secure Cookie 时，Core 拒绝启动。Caddy HTTPS 入口增加 HSTS；本地 HTTP 模式保留用于开发。

## 审计与运维

PostgreSQL `authentication_events` 保存事件类型、账号 ID、账号及来源的 HMAC 摘要和时间。用户只能查看自己的最近记录；来源摘要用于关联异常，不返回明文 IP。部署者需按实际隐私与留存要求归档或清理此表；当前不自动删除历史安全记录。

`/actuator/prometheus` 使用独立的 `METRICS_TOKEN`（至少 32 字符）进行 `Authorization: Bearer ...` 验证，该令牌不能访问业务 API；未配置时拒绝抓取。初始化脚本为新部署生成此令牌，已有部署可自行生成并加入私有 `.env`。监控工具应在容器私有网络访问 Core，无需将该端口发布到公网。

Prometheus 提供 `copilot_auth_events_total{type="login.failed"}`、`login.limited` 等事件计数，可配置失败次数异常告警。失败与限流也输出结构化警告；当前未附带通知平台或默认告警规则。

首次升级共享会话、关闭 Basic 的版本时，旧内存会话需要重新登录。平台登录凭据的管理与工作台账号会话相互独立，本轮不替换拼多多网页登录接入方式。

## 本轮验证记录

- Java 选定回归共 58 项通过，包含 12 项 HTTP 账号安全、13 项真实 Redis 会话/限流、4 项限流及代理策略，以及原有执行协调、回复安全和平台相关测试。
- Python 回归 320 项通过；React TypeScript 与 Vite 构建通过。
- Playwright 在独立 Compose 部署中验证 3 项流程：刷新保留登录与窄屏展示、密码复核后注销另一会话、临时账号改密后重新登录。弹窗测试用受控的 403 触发界面，服务端五分钟过期条件由 HTTP 测试直接覆盖。
- 临时部署使用独立数据库、Redis、账号和未绑定店铺；实测 Core 重启后同一 Cookie 仍可访问账号自己的工作空间。未连接真实店铺、调用外部模型或发送买家消息。
- 当前部署已应用 V24；独立监控令牌抓取指标返回 200，使用同一令牌访问业务接口返回 401。

这些验证覆盖本轮改动，不构成完整渗透测试、第三方安全认证或公网部署验收。
