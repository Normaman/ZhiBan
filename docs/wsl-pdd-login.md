# 拼多多店铺授权与查询会话

拼多多授权从客服工作台发起。Spring Boot 的 Java Playwright 在服务端打开浏览器，登录界面通过工作台同源 noVNC 页面展示；部署人员无需安装 Windows Python、WSL Python 或本地浏览器自动化工具。

## 首次授权

1. 登录工作台，进入店铺设置，点击「连接拼多多」。系统会打开授权页面。
2. 在授权桌面登录拼多多商家后台，并完成平台要求的验证码。
3. 回到授权页继续核对身份，确认店铺和客服账号后保存。
4. Spring Boot 在 Java 内核验 HTTP 身份和 WebSocket 认证，成功后登记连接。店铺在线后即可接收连接之后的新消息。

登录 Cookie 以 Fernet 加密格式保存在 Core 的平台凭据卷中；加密密钥和 Cookie 不返回浏览器或写入日志。登录目录已存在同店铺凭据时会校验身份后更新；密钥丢失时不会生成替代密钥。

## 商品与订单查询

商品同步、商品详情和订单状态查询均由 Spring 的拼多多适配层执行。需要商品或订单专用查询会话时，Java Playwright 从正常商家页面捕获对应只读请求，核验身份和数据范围后加密保存。订单短期请求头重放被要求验证时，先尝试一次正常浏览器读取；若浏览器成功，直接使用该次返回，不再次重放导致已取得结果丢失；若浏览器仍要求验证，再提示人工完成平台验证。

浏览器会话只用于获取平台页面正常生成的请求材料，不生成签名、不提交消息、不连接第二条聊天 WebSocket。验证码或登录过期时，操作员可从工作台重新授权；查询失败会返回明确错误或保留订单状态未知。

订单查询的错误须分开处理：

| 错误码 | 含义与处理 |
| --- | --- |
| `ORDER_SESSION_EXPIRED` | 平台明确返回登录失效；尝试刷新一次，失败后需要核验授权 |
| `ORDER_QUERY_RATE_LIMITED` | 平台返回请求频繁限制；按店铺冷却后再试，不刷新登录来反复请求 |
| `ORDER_QUERY_VERIFICATION_REQUIRED` | 平台在限制响应中返回安全验证标识；需要在连接器使用的授权浏览器完成平台验证，其他浏览器的登录不自动共享 |
| `ORDER_DETAIL_NOT_FOUND` | 当前查询接口未返回订单详情；核对当前店铺和订单，不能据此推断为已取消或未付款 |

真实响应中 `54001` 可携带 `result.verifyAuthToken`，不能统一解释成“会话过期”。安全验证标识不进入日志或返回前端；查询错误只保留固定诊断码。明确频率限制，或正常浏览器仍要求安全验证时，默认冷却 60 秒（Core 的 `PDD_ORDER_QUERY_COOLDOWN_SECONDS` 可设为 1～3600 秒），期间不再次请求受限详情接口或重新启动捕获。仍核对订单与买家归属，未取得的状态保持未知，不用旧状态或商品配送规则补造订单状态。冷却是单 Core 进程内的保护，重启后会清除。

浏览器重启后可能缺少会话 Cookie。订单查询从与当前店铺、账号及登录凭据摘要绑定的加密查询记录恢复缺失 Cookie，保留浏览器当前已有的验证状态；记录失效时才退回登录凭据。成功返回的 HTTP 与浏览器订单都包含本次 `fetched_at`，Agent 才能将它作为本次查询依据，不能把下单时间当作查询时间。

### 订单卡片提示安全验证时

1. 点击订单卡片的「查询状态」。若显示需要平台安全验证，店铺管理员点击「安全核验」，允许工作台打开弹窗。
2. 在弹出的拼多多订单页完成平台滑块验证；不要在其他浏览器中验证，验证状态需要属于本次查询浏览器。
3. 回到订单卡片，点击「已完成验证，重新查询」。成功后卡片显示实际状态，核验窗口自动关闭。已有失败草稿需要重新生成，才会使用新查询结果。
4. 不继续核验时可点击「关闭核验窗口」。这会关闭远程桌面入口，保留后台查询浏览器。

订单浏览器按店铺隔离，由单独线程管理，同店铺后续查询复用浏览器及页面，不在每次读取后关闭。每个 Core 进程最多保留两个店铺浏览器，闲置 30 分钟或被替换时释放；登录凭据更新时重建。Core 重启、释放浏览器或平台主动要求核验后，仍可能需要再次完成平台验证，不能保证永久免验证。仅管理员可以打开授权核验桌面，有店铺访问权限的客服可以只读重查。

订单页初始化所需的只读登录检查、子系统授权与平台安全检查请求可执行；退款、取消订单、发货及消息发送仍不在订单捕获的 POST 允许清单中。查询会话只保存实际捕获且在允许清单内的详情路径；请求头重放覆盖默认值，避免同时发送两份不同的 User-Agent 或 Content-Type。

## 部署依赖

Docker Compose 会在 Core 镜像中安装 Chromium、TigerVNC、noVNC 和 WebSocket 转发工具。Spring Boot 管理浏览器和桌面进程；Python Agent 不挂载平台凭据卷，也不负责平台查询、消息接收或发送。宿主机无需安装 Python Playwright。

## 安全与故障处理

- 不要复制、公开或提交 Core 数据卷中的 `credential.key`、`credentials.enc`、`product-session.enc`、`order-session.enc` 或浏览器 profile。
- Core 重启会关闭临时登录桌面；已保存的加密凭据不会因此删除。
- 连接状态显示失败时，从工作台重新打开授权页面并登录同一店铺，再确认身份。重连不会重发旧回复。
- 真实消息发送由 Spring Worker 执行，必须先通过工作台审批；登录或刷新查询会话不会启用发送。
