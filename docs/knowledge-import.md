# 知识资料导入与检索

## 变更审核、有效期与回滚

普通新增、编辑、删除和文档替换先保存为变更草稿，不立即影响线上知识。作者填写说明并提交审核，管理员查看逐条差异、可能重复的内容和适用条件后批准发布或驳回。每次处理检查草稿修订号；发布还检查基于的知识版本，避免旧草稿覆盖新版本。草稿与审核记录、历史快照及操作审计均保留。当前允许管理员审核自己的变更，适合单人店铺；没有宣称实现强制双人审批。

历史版本的「申请恢复」会生成一份新的回滚草稿，同样提交审核；不会修改原版本。管理员备份迁移和原直接发布接口属于显式管理操作，仍记录审计，不属于普通编辑草稿流程。

手动编辑可设置生效时间和失效时间。时间带时区保存，失效边界不再参与检索和回答规范；Agent 按任务创建时间固定有效资料，检索调试按当前时间筛选。未填写表示长期有效。未来生效或已失效资料仍可在已发布版本中查看，不能把「已发布」等同「当前有效」。向量索引按完整不可变版本构建，检索时仅允许有效来源，避免有效期变化导致同一版本索引指纹冲突。

重复检查仅提示同范围、同分类的相同正文或同名不同正文，不是完整语义冲突判定；管理员需要核对例外条件。商品资料保留原有商品编号绑定和权限检查。

## 检索调试

知识库中的「检索调试」可输入买家问题，限定分类、商品范围并选择关键词/混合模式，查看实际执行模式、命中顺序、正文、来源位置、知识版本和耗时。未发布草稿不参与检索；混合检索未完成时明确显示降级。回答规范在生成时直接加载，不依赖召回命中。该功能不调用生成模型，不会发送买家消息。

接口使用现有登录、CSRF 和店铺权限：

- `POST /api/v1/shops/{shop}/knowledge/search`：查询已发布有效资料。
- `GET/POST /api/v1/shops/{shop}/knowledge/proposals`：最近 30 份变更元数据/保存草稿。
- `GET /api/v1/shops/{shop}/knowledge/proposals/{id}`：差异与重复提示。
- `POST /api/v1/shops/{shop}/knowledge/proposals/{id}/decisions`：作者提交或撤回。
- `POST /api/v1/admin/shops/{shop}/knowledge/proposals/{id}/decisions`：管理员审核。

处理请求包含 `revision`、`action`、`note`、`acknowledge_conflicts`。版本冲突返回 409；知识快照始终由 Spring/PostgreSQL 保存，Python 仅负责解析与检索。

## 备份与迁移

管理员在「知识库 → 备份与迁移」可以：

- **导出知识库**：下载当前生效版本的 JSON 备份，保留全部条目、分类、商品编号、文件名、来源位置和整理方式。
- **迁移导入**：选择另一套工作台导出的备份，查看来源店铺、目标店铺、资料正文及新增、更新、跳过数量，确认后发布到当前店铺。

迁移默认合并，不清空目标已有资料；同编号但不同内容的条目默认保留目标内容，也可明确选择用备份更新。同内容且来源信息相同的条目即使编号不同也会跳过。重复迁移已经存在的资料不会创建新版本。预览后若有人更新目标知识库，提交返回版本冲突，需要重新检查。

商品扩展知识只保留原商品编号，不按标题猜测对应商品。目标店铺的商品列表缺少该编号时，整次迁移会被阻止；先同步目标商品，或明确取消「包含商品扩展知识」，仅迁移店铺规则、常见问答和回答规范。旧知识版本、旧任务和草稿引用保留；已有草稿要重新生成。

### 将 WSL 开发数据迁入 Docker

在项目根目录执行：

```sh
conda activate dl
# 只导出，不写入 Docker
python scripts/knowledge_transfer.py export

# 一条命令：导出本机备份，核对同一平台店铺，合并到 Docker
python scripts/knowledge_transfer.py migrate --yes
```

脚本沿用 `.runtime/workspace.json` 的开发模式；只在必要时启动原有开发 PostgreSQL，不启动 Java、Agent、浏览器或消息发送。备份保存在 `.runtime/exports/`，权限为仅本机用户可读写。迁移通过 Docker 工作台的管理员接口进行，默认从 `infra/.env` 读取初始管理员凭据及 `WEB_PORT`；本机管理员密码已修改时，可传 `--username 用户名` 并在提示中输入当前密码。

自动选择目标要求拼多多平台店铺编号一致且目标已经绑定。不能唯一匹配时拒绝写入；可在确认目标后传 `--target-shop 店铺编号`，编号可在「店铺与成员」查看。`--yes` 表示允许按预览计划发布；省略时会在终端显示目标与统计后询问确认。

常用选项：

```sh
# 使用已有备份，目标地址按实际部署填写
python scripts/knowledge_transfer.py migrate --archive .runtime/exports/备份文件.json --target-url http://127.0.0.1:5178 --yes

# 明确只迁移店铺资料，不迁移商品扩展知识
python scripts/knowledge_transfer.py migrate --rules-only --yes

# 导出指定开发模式中的店铺
python scripts/knowledge_transfer.py export --source-mode live --source-shop 店铺编号 --output .runtime/exports/店铺知识.json
```

备份格式版本为 `pdd-copilot-knowledge / 1`，使用 `snapshot_json` 保存原始知识快照，并以 SHA-256 检查文件内容是否损坏；校验值不是来源可信证明。迁移文件最多 20MB，合并后最多 500 条。备份只含生效的知识快照与必要来源信息，不包含原始上传文件、历史版本、向量索引、平台价格库存、聊天记录、账号密码、Cookie 或模型密钥。迁移后检索索引按新的目标知识版本重新构建。普通资料 JSON 模板仍使用「导入资料」，备份文件使用「迁移导入」。

在「知识库 → 导入资料」选择文件，系统提取文字后打开预览。资料解析不会自动发布知识或发送买家回复；分条分类在本地进行，不调用外部模型。

1. 系统提取原文，根据标题和主题边界建议拆成条目，并逐条建议发货、售后、商品参数、选购、常见问答或客服回答规范分类。
2. 查看条目和来源，编辑分类、标题及正文。含多类内容且条件关联不明的条目标为待分类；可从光标处分条，也可明确取消纳入发布。标题保留为下文上下文，默认不单独发布。
3. 商品资料须手动绑定当前店铺已同步的商品，避免混用商品。可逐条设置，也可展开批量设置；店铺规则全店适用。任何纳入发布的条目未分类、未绑定商品或正文为空时，确认按钮禁用。
4. 勾选核对确认后发布。新任务使用新版本，旧任务继续使用固定版本；旧草稿需重新生成。

上传整份文件前不需要选择资料类型，预览中的分类对应每个条目。「手动新增」为独立入口，只新增单条资料，不影响文件上传。

## 修改与删除

「已生效资料」提供始终可见的分类及数量，包括「常见问答」和「客服回答规范」。可按标题、正文或文件名搜索；左侧按文件列出条目，右侧只显示选中条目的标题、分类、适用商品、来源和正文。窄屏改为上下排列，目录与正文各自有界滚动。正文保留段落、换行及简单 Markdown 标题和列表，不执行上传的 HTML。发布后定位刚更新的条目。阅读区可点击「编辑」修改名称、正文、分类和关联商品，保存后立即发布新版本；保留原始文件名、哈希及来源位置，标记为手动整理。再次导入同名文件会替换这些手动修改。

点击条目「删除」只移除这一条；文件标题旁的「删除整份」移除该文件全部条目，不影响其他文件。确认窗口显示范围和数量，取消不会修改知识。允许删除最后一条资料，当前版本变为空列表；刷新不会重新激活旧知识。

这里的删除是从当前知识快照移除，历史版本、历史向量及旧草稿引用保留用于追溯，不是物理清除历史数据。新建或重新生成的 Agent 任务使用新的知识版本，不再检索被移除条目；已经启动的任务及旧草稿仍绑定原版本，需要重新生成。向量索引按版本隔离，新版本首次查询时按现有流程构建。

编辑、删除、文档预览和 JSON 导入均固定开始操作时的基线版本。其他人先发布时，旧窗口提交返回 409，不覆盖新资料；关闭窗口并重新打开核对后再操作。知识删除仍复用完整快照发布接口，空列表必须携带 `base_version`；历史客户端省略基线时不能清空资料。

## 文件支持

| 格式 | 处理方式与限制 |
| --- | --- |
| TXT、MD | UTF-8（含 BOM）或 GB18030 文本，按空行分段；Markdown 作为文字，不执行 HTML、不抓取链接 |
| CSV | 首个非空行视为列名，每行重复列名，保留带引号的换行；只支持逗号分隔 |
| DOCX | 按正文顺序提取段落和表格，表格首行视为列名；图片、批注、页眉页脚不导入 |
| XLSX | 按工作表和行提取，首个非空行视为列名；拒绝含公式的工作簿，请先另存为数值；不执行宏或公式、不读取外部链接 |
| PDF | 提取文字层并记录页码；加密文件拒绝。扫描图片不做 OCR；完全无文字时拒绝，部分页面无文字时明确提示遗漏页数量。复杂表格、多栏排版必须人工核对 |
| JSON | 保留已有模板导入，最多 1 MB；在发布前可展开每条内容核对 |

文档最多 5 MB、累计提取 20 万字符、500 段；PDF 最多 100 页，Excel 最多 30 张表，每张表最多 5000 行、100 列。压缩文件解压总大小最多 30 MB、2000 个成员。超限拒绝整次导入，不悄悄发布部分资料。正文超过 1600 字符时优先在后半段换行/句号处分割，否则按长度切分，无重叠；一段的条件与例外可能因此分开，预览时需核对并编辑。

不支持旧版 DOC/XLS、图片、扫描件 OCR。不要把库存和价格作为固定承诺录入知识库；这两类问题仍使用实时平台工具。

## 混合资料自动整理

本地规则根据明确词汇和标题识别主题，在句号、分号、逗号或换行处遇到清晰主题变化时分条。条件、例外与依赖说明尽量跟随前面的条款；多类条件无法安全分开的内容保留原文并等待人工分类。退货运费归售后，不误归配送；商品事实与选购建议分别处理。

规则无法分类且不是明显混合内容时，如启用本地 RAG，会尝试本地 BGE 分类建议。使用六类说明的向量相似度和保守间隔门槛，不将相似度解释为正确率。模型忙、超时或不确定时保持待分类。所有原文都需人工核对，自动分类不能证明政策正确，也不会自动推断关联商品。

## 客服回答规范

分类标识为 `response_guidelines`，属于全店资料，不绑定商品，不能与发货或售后事实分类混在同一条目。适合录入称呼、礼貌、回复长度、措辞与禁止夸大承诺，例如“称呼使用您好；先回答问题；不承诺未经核实的时效”。商品发货与运费仍查询平台，不能把话术示例当事实。

每次模型生成、依据复核和必要的一次修正均携带当前任务版本的全部回答规范；单独标记为规范引用，不计作业务事实证据。最多 30 条、累计 16000 字符，超过时明确转人工，不静默丢弃；未配置模型时不通过简单原文摘录假装已应用规范。规范及知识会发送给管理员配置的模型，人工审批和退款等强制转人工保持有效。模型检查仍可能误判，不能保证所有表达要求都被执行。

默认回答要求贯穿生成和复核：直接回答当前问题，通常 1–3 句、目标 120 字以内；省去重复问题、查询过程、无关推荐和客套。必要的范围、条件与例外，以及买家明确要求的详细说明不受机械字数限制。不直接截断模型文本。复核出现 `reply_verbosity` 或规范问题时，最多用原有依据修正一次，修正后再次检查；仍不通过则交人工，不把未通过的内容当作可发送草稿。

会话页将「回复依据」与「规范检查」分开，默认收起。前者只统计业务事实引用，后者说明检查状态，按需展开店铺规范。多条咨询逐条检查，只在本份草稿覆盖的问题全部通过时显示检查通过；未调用模型的摘录显示尚未检查；人工编辑后改为待人工核对，原检查不代表修改后的内容已通过。正文与版本仍保留用于追溯。

## 常见问答与回答规范怎么写

「常见问答」（`faq`）保存已核实的固定问题答案及适用范围；「客服回答规范」约束所有模型回复的表达。二者在同一知识库中维护，但一条条目不能同时归为规范和事实。现有条目不自动改类，可在编辑时调整。

- 回答规范示例：先回答结论，通常 1–3 句；只保留当前问题的要点和必要条件；不重复寒暄，不做未经核实的承诺。
- 常见问答格式：`问题：……`、`答案：已核实的答复`、`适用范围：商品或条件`。例如「保真吗」必须录入店铺已经核实的正品说明及适用商品，不能仅凭一条“统一回复保证正品”的话术做保证。此处不提供预设的保真承诺。

模型用 `search_customer_service_knowledge(topic="faq")` 对当前固定版本做相关检索，保留引用；没有适用条目时补充资料或交人工。价格、库存和商品配送依然查询平台，固定问答不能覆盖实时结果。上传的混合文件会建议分类，问题与紧随的答案保持在一起；仍需人工核对适用范围后发布。

## 来源、更新与存储

浏览器将文件内容以 Base64 JSON 提交给 Spring 的店铺权限接口，再由 Python 解析。解析不调用外部模型。文件仅在内存与受限子进程中处理，不保存原文件；PostgreSQL 保存发布后的正文、文件名、SHA-256、原始段/页/行位置和知识版本。编辑后的内容沿用原始来源位置；哈希标识上传的原文件，并非编辑后正文校验值。

同名文件再次发布会整体替换该文件的所有旧条目，包括此前不同分类和商品下的条目，避免混合文件变短或分类调整后遗留旧规则。预览与确认发布前均明确说明；其他文件保留，历史知识版本可追溯。改文件名会作为另一个来源导入。重复发布相同文件不会重复累加条目，但仍建立一次发布版本。JSON 按条目编号替换。

发布支持 `base_version` 乐观锁，浏览器会携带当前版本。冲突返回 409，不覆盖别人的修改；旧客户端未携带该字段时仍兼容原完整快照发布接口。不可变历史版本用于追溯，不提供原文件下载。

## Agent 如何查询

先按 Spring 提供的店铺知识版本和商品/规则类别限定候选。启用 `RAG_ENABLED=1` 后，本地 BGE Embedding 与 pgvector 提供语义召回，BM25 提供关键词召回，经过 RRF 融合和本地 BGE CrossEncoder 重排后最多返回 5 条。详情、部署与边界见 [混合检索说明](hybrid-rag.md)。

未启用时保留 BM25；向量服务不可用时明确标为 `bm25_degraded`。知识库页面显示检索模式，草稿工具执行记录显示实际使用模式。模型生成阶段才将命中的正文与必要会话发给管理员配置的模型；本地向量化和重排不上传资料。引用保留文件名与页/段/行位置，最终仍须人工审批。

## 工程实现

- `apps/web/src/components/DocumentImport.tsx`：有界预览对话框、编辑、分类、商品绑定和明确发布。
- `KnowledgeController` / `AgentClient`：店铺访问检查、输入长度限制和内部解析请求转发。
- `KnowledgeService`：来源字段校验、商品绑定、版本冲突检查、不可变快照发布。
- `copilot/knowledge/documents.py`：格式提取与分段，使用 pypdf、python-docx、openpyxl。
- `copilot/knowledge/organize.py`：本地按主题建议分条、保留上下文和来源、规则及可选语义分类。
- `copilot/knowledge/import_service.py`：每个 Python 进程最多两个解析子进程；20 秒墙钟时间、15 秒 CPU 时间、768 MB 地址空间限制；异常只返回固定错误码。实现针对当前 Linux/WSL 部署，不是通用 Windows 解析器，也不是操作系统安全沙箱。
- `copilot/knowledge/retrieval.py`：在已授权候选集上执行确定性相关性排序。

解析库行为参考：[pypdf 文字提取与 OCR 边界](https://github.com/py-pdf/pypdf/blob/main/docs/user/extract-text.md)、[python-docx 正文顺序](https://python-docx.readthedocs.io/en/develop/api/document.html)、[openpyxl 只读与公式选项](https://openpyxl.readthedocs.io/en/3.1/api/openpyxl.reader.excel.html)。

## 草稿修改与重新提交

在「变更审核」中打开自己创建的草稿，选择「编辑草稿」；已驳回或已撤回的变更可修改后重新提交。待审核的变更需先撤回，已发布版本不能原地修改。编辑器支持新增、修改和移除条目，保存后仍需提交审核、由管理员发布。

当前知识库已更新时，编辑器按原基线、当前版本和草稿进行三方合并，保留其他人的无关变更；同一条目同时被修改时逐项选择「保留当前」或「采用草稿」。保存和审批均校验版本，期间版本再次变化返回 409，不能覆盖新版本。

修改与审核记录保留各次快照及处理说明；V27 升级前的变更只能回填当时保留的当前修订，无法恢复此前未记录的修订。接口为 `PUT /api/v1/shops/{shop}/knowledge/proposals/{id}`，请求包含 `revision` 和完整的 `knowledge`（`version`、`base_version`、`entries`）。
